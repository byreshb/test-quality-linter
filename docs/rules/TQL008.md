# TQL008 DuplicateTestBody

**Default severity:** WARN

## What it catches

Two test methods in the same class whose bodies are identical once whitespace and comments are
normalised away:

```java
@Test
void savesWithTwoItems() {
  Order order = service.save(new Order("widget", 2));
  assertEquals(2, order.quantity());
}

@Test
void savesAnotherOrder() {   // flagged: identical to savesWithTwoItems
  Order order = service.save(new Order("widget", 2));
  assertEquals(2, order.quantity());
}
```

Only bodies of two or more statements are compared, so two trivial one-line tests (a common,
usually harmless pattern) are not flagged. Comparison is per class, and per normalised body: a
group of three or more identical methods produces one finding per extra copy, naming the first
method in source order as the original.

## Why it matters

A generator asked to cover several scenarios sometimes produces the same test body under a
different name for each one, which looks like coverage but adds no new proof. Keeping the
duplicate also means a bug fixed in one copy is silently missed in the other.

## Bad

```java
@Test
void computesTheTotal() {
  Invoice invoice = new Invoice(List.of(new Line(10), new Line(20)));
  assertEquals(30, invoice.total());
}

@Test
void computesTheTotalAgain() {
  Invoice invoice = new Invoice(List.of(new Line(10), new Line(20)));
  assertEquals(30, invoice.total());
}
```

## Fixed

```java
@Test
void computesTheTotal() {
  Invoice invoice = new Invoice(List.of(new Line(10), new Line(20)));
  assertEquals(30, invoice.total());
}

@Test
void computesTheTotalWithAnEmptyLine() {
  Invoice invoice = new Invoice(List.of(new Line(10), new Line(0)));
  assertEquals(10, invoice.total());
}
```

## Options

None.
