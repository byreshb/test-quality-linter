# TQL002 ConstantAssertion

**Default severity:** ERROR

## What it catches

An assertion whose operands are all literals or compile-time constants, so its outcome was
decided when the test was written and nothing the code under test does can change it:

- `assertEquals(2, 1 + 1)`, `assertEquals("ab", "a" + "b")`, `assertNotEquals(1, 2)`.
- `assertEquals(EXPECTED, 4)` where `EXPECTED` is a `static final` field of the test class
  initialised with a constant.
- `assertTrue(1 < 2)`, `assertFalse(1 > 2 || false)`.
- `assertThat(1 + 1).isEqualTo(2)`, `assertThat("abc").startsWith("a")`,
  `assertThat(LIMIT).isGreaterThan(3)`.
- Hamcrest `assertThat(3, greaterThan(2))`, `assertThat("a", is("b"))`.

A constant is a literal, a unary, binary, conditional or cast expression over constants, or a
`final` field of the same file whose initialiser is constant. Identical operands
(`assertEquals(1, 1)`) and bare `assertTrue(true)` are reported by TQL001 instead, never twice.

## Why it matters

A test that compares two constants is a test of the Java compiler. It is often left behind when
the call to the code under test was removed, or generated to make an "expected value" appear
without wiring it to anything.

## Bad

```java
@Test
void computesTotal() {
  assertEquals(30, 10 + 20);
  assertThat("EUR").isEqualTo("EUR");
}
```

## Fixed

```java
@Test
void computesTotal() {
  Invoice invoice = new Invoice(List.of(new Line(10), new Line(20)));
  assertEquals(30, invoice.total());
  assertThat(invoice.currency()).isEqualTo("EUR");
}
```

## Options

None.
