# TQL009 DisabledWithoutReason

**Default severity:** WARN

## What it catches

A test or test class disabled with `@Disabled` (JUnit 5) or `@Ignore` (JUnit 4) and no reason:

```java
// not compiled
@Disabled
@Test
void flakyOnCi() { ... }
```

A marker annotation, an empty string (`@Disabled("")`), and a named `value`/`reason` argument
are all recognised the same way. Given a reason, the finding is not raised for that alone; when
the `maxAgeDays` option is set and the file is on disk inside a git repository, the annotation is
also flagged once it has stood, reason or not, for longer than that many days, using `git blame`
on the annotation's line.

## Why it matters

A disabled test with no reason gives the next person nothing to go on: is it flaky, blocked by a
known bug, obsolete, or just broken and forgotten? A test that has been disabled for months,
even with a reason, is worth revisiting: either fix it or delete it, since a permanently skipped
test provides no coverage while still showing up as "present" in the suite.

## Bad

```java
// not compiled
@Disabled
@Test
void handlesConcurrentUpdates() { ... }
```

## Fixed

```java
// not compiled
@Disabled("Flaky under load; tracked in ISSUE-482")
@Test
void handlesConcurrentUpdates() { ... }
```

## Options

| Option | Type | Default | Meaning |
|--------|------|---------|---------|
| `maxAgeDays` | integer | `0` (off) | Also flag a `@Disabled`/`@Ignore`, reason or not, once it has stood for more than this many days. Needs the file on disk inside a git repository and `git` on the path; otherwise the age check is silently skipped. |

```yaml
rules:
  TQL009:
    options:
      maxAgeDays: 90
```
