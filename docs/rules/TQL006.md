# TQL006 HardcodedSleep

**Default severity:** WARN

## What it catches

A fixed delay where a wait for a condition belongs:

- `Thread.sleep(...)` and `TimeUnit.SECONDS.sleep(...)` (any unit, statically imported or not);
- Guava's `Uninterruptibles.sleepUninterruptibly(...)`;
- Playwright's `page.waitForTimeout(...)` and `frame.waitForTimeout(...)`;
- an Awaitility chain that sets a `pollDelay` and then waits for nothing:
  `await().pollDelay(2, SECONDS).until(() -> true)`, an empty `untilAsserted` block, or no
  `until` at all.

## Why it matters

A sleep is a guess about how long the other side needs. Too short and the test is flaky; too
long and the suite is slow; and either way the test asserts nothing about the event it was
waiting for. Waiting for the condition itself is both faster and a real check.

## Bad

```java
@Test
void processesTheMessage() throws Exception {
  queue.send("hello");
  Thread.sleep(2000);
  assertThat(consumer.received()).contains("hello");
}
```

## Fixed

```java
@Test
void processesTheMessage() {
  queue.send("hello");
  await().atMost(Duration.ofSeconds(5))
      .untilAsserted(() -> assertThat(consumer.received()).contains("hello"));
}
```

## Options

| Option | Type | Default | Meaning |
|--------|------|---------|---------|
| `maxMillis` | integer | `0` | `Thread.sleep` calls with a literal argument of at most this many milliseconds are tolerated. |

```yaml
rules:
  TQL006:
    options:
      maxMillis: 50
```
