# TQL012 MockOfTypeUnderTest

**Default severity:** WARN

## What it catches

The class named in the test class name is itself replaced by a mock, through a Mockito or
EasyMock `@Mock`/`@Spy` field, or a `mock(...)`, `spy(...)`, `createMock(...)`,
`createNiceMock(...)` or `createStrictMock(...)` call:

```java
class OrderServiceTest {
  @Mock
  OrderService orderService;   // flagged: OrderService is the class under test
}
```

The class under test is derived from the test class name by stripping one of the suffixes
`ITCase`, `TestCase`, `Tests`, `Test` or `IT`; a class whose name does not end in one of them is
not checked. Mocking a collaborator (`@Mock OrderRepository repository;`) is normal and not
flagged.

## Why it matters

When the class a test is named after is mocked, the test exercises Mockito's or EasyMock's
bookkeeping, not the real implementation. This is sometimes deliberate (a partial mock to
isolate one method), which is why the severity is WARN rather than ERROR and the finding needs a
human to confirm it.

## Bad

```java
class OrderServiceTest {
  @Mock
  OrderService orderService;

  @Test
  void saves() {
    when(orderService.save(any())).thenReturn(new Order("widget", 2));
    assertNotNull(orderService.save(new Order("widget", 2)));
  }
}
```

## Fixed

```java
class OrderServiceTest {
  @Mock
  OrderRepository repository;

  @InjectMocks
  OrderService orderService;

  @Test
  void saves() {
    Order saved = orderService.save(new Order("widget", 2));
    verify(repository).save(saved);
  }
}
```

## Options

None.
