# TQL010 ContradictoryMessage

**Default severity:** INFO

## What it catches

An `assertTrue`/`assertFalse` message that says the opposite of what the assertion checks:

```java
assertTrue(order.isValid(), "order should not be valid");   // flagged
assertFalse(order.isValid(), "order should be valid");      // flagged
```

`assertTrue` is flagged when its message contains "should not", "shouldn't", "must not",
"mustn't" or "never"; `assertFalse` is flagged when its message contains "should" but no form of
"not". Either JUnit argument order (message first, as in JUnit 4, or message last, as in JUnit 5)
is recognised. This is a plain text heuristic over the literal message, not a semantic check, so
it stays at INFO: it usually means the message was not updated when the condition was written or
flipped, but it can occasionally be a coincidence of wording.

## Why it matters

A contradictory message is confusing on a failure: the reader cannot tell, from the message
alone, which of the condition or the words is wrong, and has to go read the code either way. It
is often a sign the assertion itself was flipped by mistake.

## Bad

```java
assertTrue(response.isEmpty(), "response should not be empty");
```

## Fixed

```java
assertFalse(response.isEmpty(), "response should not be empty");
```

## Options

None.
