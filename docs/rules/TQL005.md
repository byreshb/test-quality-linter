# TQL005 VerifyOnly

**Default severity:** WARN

## What it catches

A test that verifies a mock interaction and asserts nothing else:

```java
@Test
void savesTheOrder() {
  service.save(order);
  verify(repository).save(order);
}
```

Any of Mockito's `verify`, `verifyNoInteractions`, `verifyNoMoreInteractions`,
`verifyZeroInteractions` or `verifyAll` counts as a verification. A test that also contains a
real assertion (JUnit, AssertJ, Hamcrest, Truth, Playwright), or that declares an expected
exception, is not flagged. A test with a verification and nothing else is not flagged by
[TQL003](TQL003.md) either, since a verification is itself accepted there as "asserting
something"; TQL005 is the finer-grained signal that the something was only an interaction.

## Why it matters

Verifying that a method was called confirms the collaborator was used, but not that it produced
the right outcome, or that the outcome reached the rest of the system correctly. A save that is
verified but whose result is never checked can silently save the wrong data.

## Bad

```java
@Test
void savesTheOrder() {
  service.save(order);
  verify(repository).save(order);
}
```

## Fixed

```java
@Test
void savesTheOrder() {
  Order saved = service.save(order);
  verify(repository).save(order);
  assertThat(saved.status()).isEqualTo(Status.CONFIRMED);
}
```

## Options

None.
